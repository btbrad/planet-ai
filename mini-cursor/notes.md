# MCP 笔记

## 什么是 MCP
MCP（Model Context Protocol，模型上下文协议）是一个开放协议，用于在 LLM 应用与外部数据源、工具之间建立标准化的连接方式。可以把它理解为「AI 应用的 USB-C 接口」：一端是宿主应用（Host，如 IDE、聊天客户端），另一端是提供能力的服务端（Server）。

## 核心概念
- **Host（宿主）**：运行 LLM 并管理连接的应用程序。
- **Client（客户端）**：宿主内部与单个 Server 建立 1:1 连接的组件，负责协议握手与消息路由。
- **Server（服务端）**：对外暴露具体能力的一方，通常是轻量进程。
- **Tools（工具）**：可被模型调用的函数，由模型决定何时调用（可执行写操作）。
- **Resources（资源）**：只读的上下文数据，如文件内容、数据库记录，由应用决定如何注入。
- **Prompts（提示模板）**：预定义的提示词/工作流模板，通常由用户显式触发。

## 传输方式
- **stdio**：通过标准输入/输出通信，适合本地进程，简单高效。
- **Streamable HTTP / SSE**：适合远程服务，支持多客户端接入。

## 典型工作流
1. 客户端发起初始化握手，双方交换协议版本与能力声明。
2. 客户端通过 `tools/list`、`resources/list`、`prompts/list` 发现可用能力。
3. 模型根据任务选择工具，客户端通过 `tools/call` 发起调用。
4. 服务端返回结果，客户端将结果回传给模型继续推理。

## 价值
- 一次实现、多处复用，避免为每个 LLM 应用重复对接。
- 权限与数据留在本地，安全边界清晰。
- 生态可组合：文件系统、数据库、Git、浏览器等能力皆可封装为 Server。
